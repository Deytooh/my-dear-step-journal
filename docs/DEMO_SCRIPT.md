# Demo script

Target approximately three minutes; this is an editing target, **not an official portal limit**. Verify the logged-in submission form. Use fictional records and an owned meal photo, not real health data.

## Preparation

Follow SETUP_AND_ENV: configure key/model/quota/private bucket, run the live smoke test and test account separation. Use a disposable guest profile for the visible example home, and a separate dedicated signed-in test account for paid AI. Prepare a fictional purchase/stock lot in that test account if inventory is shown. The guest demo anchor is the displayed local Seoul date at reset. Record the anchor in the recording notes. Keep exact source inputs visible; no prerecorded fallback disguised as live inference.

## One central journey

On first launch choose English (or the judge's preferred language). Finish or skip the optional introduction, open Momo and use its sign-in link before the AI portion. Resume the fictional draft only when that choice is offered, then give fresh consent. Use the configured dedicated test account; wait for its records to finish syncing before AI memory retrieval.

A short English text for rehearsal:

> Fictional demo. Today I weighed 78.2kg and felt tired after a walk at the cafe. Yesterday evening I had an injection, but I do not remember the medication, dose or site.

French and Korean equivalents can be typed or dictated. Keep dates relative to the displayed local day. To show mixed text/photo input, attach an owned meal photo and add a fictional meal caption before organizing; explicitly choose the amount eaten in review. Do not treat this script as a guarantee of a particular live model output.

| Time | Screen action | Suggested narration |
| --- | --- | --- |
| 0:00-0:15 | First-launch language choice; Today and central Momo composer | "My Dear Step turns a few words and photos into a journal I can inspect." |
| 0:15-0:55 | In the signed-in test account, type the fictional day (optionally with an owned meal photo), show consent and organize | "Momo proposes entries from this input. I decide what gets saved." Name the actual returned Meta model only after the live call succeeds. |
| 0:55-1:35 | Review all suggested entries; correct 78.2 to 78.3; check the proposed date and unknown injection fields; choose an eaten fraction if a meal is present | "Missing facts stay unknown. I can correct each suggestion or leave it out. Food and energy estimates need my review." |
| 1:35-2:05 | Confirm once; show local/account status; reload, reopen an entry and expand Source | "The original words or photo and my correction remain linked to the saved entry." Claim account sync only after its visible success state. |
| 2:05-2:35 | Find my entries: search cafe or a saved amount; open the original. Optionally show consented Momo retrieval after sync | "Keyword search works without AI. Momo can also retrieve existing entries from my synced journal." |
| 2:35-3:00 | Briefly show manual logging/Undo and export | "Manual entry stays available, and I control confirmation, corrections and export." |

If a live result misses a fact, show its missing field or add it manually; do not present a prepared result as that call's output. If purchase stock is included, missing medication/unit means stock needs review. A pen count is never presented as a dose count.

Finish: "Less typing, review before saving, and a source I can return to."

## Short fallback (60–90 seconds)

Show Today → manual meal with photo and an explicitly user-entered estimate → half-portion calculation → source after reload → calendar/history → export. If the live provider is unavailable, state that clearly and show the implemented manual fallback. This fallback does **not** establish the required runtime Meta use for submission; record the live portion only after configuration works.

## Record honestly

- No medication recommendations, causal chart claims, meal grades, calorie budgets or fake integrations.
- “Browser voice transcription,” not native audio-to-Meta.
- “In-app user-set schedule,” not background notifications.
- “Photo estimate,” not measured calories or a confidence interval.
- Repo/video/live-app URLs must be filled from actual accessible destinations.
